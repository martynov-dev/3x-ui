# 3X-UI — форк martynov-dev

Форк панели [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui) для управления Xray/VPN и связанным с ним сайтом nginx из одной панели.

Основа форка — **3X-UI v3.10.2**, коммит [`608ef4e4010bf83e2e78328e08f77efc051ad4d7`](https://github.com/MHSanaei/3x-ui/commit/608ef4e4010bf83e2e78328e08f77efc051ad4d7). Это версия исходного проекта, от которой начаты доработки форка.

## Отличия форка

- **Без рекламы:** удалены рекламные блоки, раздел спонсоров и запросы к серверу рекламы.
- **Бэкапы панели и сайта:** ручное создание и расписание, выбор дополнительных файлов, хранение локальных копий и отправка по SSH. Бэкап включает базу, файлы панели, nginx, сайт и сертификаты.
- **Настройка сайта из панели:** выбор существующего конфига nginx, редактирование конфига и `index.html`, HTTP-шаблон, проверка `nginx -t` и откат файлов при ошибке применения.
- **Обновления из форка:** установщик и обновлятор скачивают сборки из **martynov-dev/3x-ui**. Изменения оригинала можно отдельно сливать в исходники форка.

## Установка и обновление

Перед установкой в этом форке должна успешно завершиться сборка **Release 3X-UI** в GitHub Actions и появиться релиз с бинарными файлами.
Для текущей ветки `main` сборка публикует `dev-latest`:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/martynov-dev/3x-ui/main/install.sh) dev-latest
```

Обновление существующей установки на сборку этого форка:

```bash
XUI_UPDATE_TAG=dev-latest bash <(curl -fsSL https://raw.githubusercontent.com/martynov-dev/3x-ui/main/update.sh)
```

Стабильные версии устанавливаются по тегам релизов, опубликованным **в этом форке**. Релизы upstream не подставляются автоматически. В панели канал Dev проверяет сборки этого форка.
Перед заменой установленной панели сохраните резервную копию.

## Полные бэкапы

Откройте **«Бэкапы и сайт → Полные бэкапы»**, выберите интервал и число локальных копий, затем включите расписание. Расписание работает, пока запущена панель, и проверяется раз в минуту; первый бэкап выполняется после включения. После перезапуска просроченный запуск выполняется на следующей проверке.

Локальное хранилище: `/etc/x-ui/full-backups` (или `$XUI_DB_FOLDER/full-backups`). Архивы имеют права `0600`, каталог — `0700`.

Состав архива:

- `database/x-ui.db` — согласованный снимок SQLite, либо `database/x-ui.dump` — дамп PostgreSQL;
- `files/` — файлы с сохранением исходной структуры путей: каталог данных панели, исполняемый файл и bin, настройки запуска службы, сертификаты панели и подписок;
- конфигурация nginx, каталоги сайтов и сертификатов из настроек; доступные статические пути `root`, `alias` и сертификатов дополнительно определяются через `nginx -T`;
- цели симлинков, в том числе внешние сертификаты;
- `manifest.json` — версия панели, дата, источники и отсутствующие пути.

Каталоги логов, старые архивы и рабочие файлы SQLite WAL/SHM исключаются. Это резервная копия приложения и выбранных файлов, а не образ ОС. Динамические пути nginx с переменными и файлы других сервисов нужно добавить вручную. Ошибка чтения существующего файла прерывает создание архива.

Для удалённой копии укажите SSH-адрес ПК с Linux/WSL, роутера или сервера, порт, пользователя, существующий каталог и путь к приватному ключу **на сервере панели**. На удалённой стороне нужны совместимый с scp сервер и POSIX-команда `mv`; обычная SSH-оболочка Windows не поддерживается. На сервере панели нужны команды `scp` и `ssh`, вход по ключу и заранее проверенный ключ устройства в `known_hosts`. Устройство должно быть доступно во время отправки. Пустой SSH-адрес означает только локальное хранение. Удалённое удаление старых копий настраивается на устройстве назначения. Незавершённая отправка имеет суффикс `.partial`, ошибка видна в панели; локальная копия сохраняется.

Архив содержит пароли, ключи и настройки клиентов. Передача по SSH шифруется; сам архив на диске не зашифрован.

### Восстановление

Архив полного бэкапа нельзя импортировать кнопкой импорта базы. Скачайте его, проверьте `manifest.json`, установите совместимую версию панели/nginx и остановите панель. Верните файлы из `files/` в соответствующие абсолютные пути, сохраняя владельцев, права и симлинки. Для SQLite верните снимок из `database/` на путь базы панели при остановленной службе; для PostgreSQL используйте штатное восстановление дампа. Проверьте `nginx -t`, затем запустите службы. Восстановление полного архива пока выполняется вручную; перед применением обязательно проверьте его на отдельной установке.

## Сайт nginx

nginx должен быть уже установлен и запущен. В разделе сайта можно выбрать обнаруженный активный конфиг или указать путь внутри `/etc/nginx` и каталог внутри `/var/www` либо `/usr/share/nginx/html`. Кнопка чтения загружает существующие файлы. Главный `nginx.conf` редактор не изменяет.

HTTP-шаблон создаёт сайт на порту 80: направьте DNS домена на сервер и обеспечьте доступ к порту. Для HTTPS укажите существующие сертификаты и нужные директивы в редакторе. Для заглушки за Xray fallback задайте согласованный с Xray локальный порт. Автоматическая выдача сертификатов и перенастройка inbound Xray не выполняются.

Перед применением проверяется текущая конфигурация, затем новая; при ошибке записи/проверки/команды reload возвращаются прежние файлы. Для файлов в `sites-available` должно существовать включение через `sites-enabled` или `include`. Не создавайте второй сервер с конфликтующим доменом/портом. Редактор меняет `index.html`; остальные ресурсы сайта остаются на диске и попадают в бэкап вместе с каталогом.

## Получение изменений upstream

Доработки хранятся в ветке форка. Для ручного слияния изменений исходного проекта сначала сохраните свои изменения коммитом и убедитесь, что рабочая папка чистая:

```bash
git remote add upstream https://github.com/MHSanaei/3x-ui.git # один раз
git fetch upstream
git switch main
git merge upstream/main
```

Разрешите возможные конфликты, выполните проверки проекта и затем отправьте ветку в свой форк. Слияние сохраняет историю ваших доработок, но совместимость с любыми будущими изменениями upstream требует проверки. Не заменяйте ветку форка принудительным сбросом на upstream. Обновление установленной панели выполняется из собранных релизов форка; это отдельный шаг от слияния исходников.
