# Изолированная проверка форка в Docker

Стенд содержит панель с nginx и отдельный SSH/SFTP-сервер для приёма архивов. Используются собственные Docker volumes; папки `db`, `cert`, `acme` обычной установки не подключаются. Порты панели и сайта опубликованы только на localhost.

Из корня репозитория выполните:

```powershell
python scripts/docker-test/smoke.py --full
```

Нужны запущенный Docker Desktop в режиме Linux-контейнеров и Python 3. Одна команда собирает текущие исходники, запускает изолированный стенд, проверяет типы и lint интерфейса, формы, навигацию, переводы, тесты восстановления в Linux и полный интеграционный сценарий ниже. Node.js и Go на компьютере не нужны. При ошибке команда завершается с ненулевым кодом; стенд остаётся для разбора. Это запуск по команде, не фоновое расписание и не GitHub Actions.

Для повторения только интеграционного сценария на уже запущенном стенде, **без пересборки новых правок**:

```powershell
python scripts/docker-test/smoke.py
```

Для ручной проверки без Python:

```powershell
docker build -t fork-3x-ui:test .
docker compose -p fork-backup-test -f compose.test.yml up -d --build
```

После запуска откройте браузер:

- Панель: <http://127.0.0.1:12053/>
- Логин: `dev-admin`
- Пароль: `LocalTest-3xui-2026`
- Сайт-заглушка: <http://127.0.0.1:18080/>

Учётные данные предназначены только для этого локального стенда. Для входа в панель не нужен установочный скрипт или опубликованный релиз.

## Что можно проверить вручную

1. Откройте **Бэкапы и сайт**. Нажмите **Создать бэкап сейчас**, затем скачайте архив по ссылке.
2. Включите расписание, задайте интервал и число локальных копий, сохраните. После автоматической проверки расписание выключено, чтобы тестовые архивы не накапливались без надобности.
3. Для проверки отправки по SSH используйте подготовленного получателя:

   | Поле | Значение |
   |---|---|
   | Адрес | `backup-target` |
   | Пользователь | `backup` |
   | Порт | `22` |
   | Каталог | `/srv/backups/3x-ui` |
   | Ключ | `/root/.ssh/backup_ed25519` |

   Сохраните и создайте бэкап. Посмотреть полученные копии:

   ```powershell
   docker compose -p fork-backup-test -f compose.test.yml exec backup-target ls -lh /srv/backups/3x-ui
   ```

4. Укажите несуществующий каталог получателя и повторите. Панель должна показать ошибку отправки и оставить архив для скачивания. Верните правильный каталог и сохраните.
5. На вкладке **Сайт nginx** выберите `/etc/nginx/http.d/3x-ui-test.conf`, каталог `/var/www/3x-ui-site`, нажмите **Прочитать файлы по этим путям**. Измените `index.html`, нажмите **Проверить и применить** и откройте сайт на порту `18080`. Не заменяйте конфиг шаблоном, если хотите сохранить его текущую структуру.
6. Попробуйте ошибочную директиву nginx. Применение должно завершиться ошибкой, прежний сайт должен продолжать открываться.

## Что делает автоматическая проверка

`smoke.py` проверяет аутентифицированный API, применение nginx с HTTP-запросом, откат некорректного конфига, создание и скачивание реального архива, целостность SQLite, наличие бинарника/конфига/сайта, права архива, передачу по SSH с SHA256, отсутствие окончательных `.partial`, ошибку доставки с сохранением локальной копии, локальную ротацию и сохранность настроек после перезапуска. Затем делает расписание просроченным **в тестовой базе**, ждёт настоящий запуск планировщика и проверяет доставку.

Последний проверенный локальный архив сохраняется в `.cache/docker-test-last.tar.gz`. Все данные и ключи стенда тестовые. Скрипт меняет настройки тестовой панели и сайт; не направляйте его на рабочую установку.

Панель запускается с `UMask` и пределом capabilities из `x-ui.service.debian`; проверка сайта каждый раз создаёт новые вложенные каталоги и проверяет их права и HTTP-ответ. Это воспроизводит ограничения процесса, но стенд работает на Alpine и не проверяет установку, остальные ограничения systemd или полное восстановление Ubuntu/Debian. Для этого нужна отдельная подходящая VM. Восстановление только базы через старое окно дашборда также не равно восстановлению всего сервера.

Автоматические проверки находят поломки сценариев и форм. Оценку понятности текста и удобства интерфейса человеком они не заменяют.

## Остановить и запустить снова

```powershell
docker compose -p fork-backup-test -f compose.test.yml stop
docker compose -p fork-backup-test -f compose.test.yml start
```

Чтобы удалить контейнеры, сохранив тестовые данные:

```powershell
docker compose -p fork-backup-test -f compose.test.yml down
```

Чтобы **удалить все тестовые данные**, добавьте `--volumes` к последней команде. Не используйте этот вариант, если хотите сохранить созданные тестовые архивы.
