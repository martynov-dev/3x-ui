# 3X-UI — форк martynov-dev

Форк [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui) — панели управления Xray/VPN. Цель форка: убрать рекламу, добавить резервное копирование панели вместе с nginx и сайтом-заглушкой и управлять этим сайтом через панель.

Основа — **3X-UI v3.10.2**, коммит [608ef4e4010bf83e2e78328e08f77efc051ad4d7](https://github.com/MHSanaei/3x-ui/commit/608ef4e4010bf83e2e78328e08f77efc051ad4d7). Это версия оригинала, от которой начата разработка форка.

## Чем отличается от оригинала

- Удалены рекламные блоки, раздел спонсоров и запросы для загрузки рекламы.
- Добавлены ручные и автоматические бэкапы: база данных, файлы панели, конфигурация nginx, сайт и сертификаты. Можно задать интервал, число локальных копий, дополнительные пути и отправку на другое устройство по SSH.
- Добавлен раздел **«Бэкапы и сайт»**: выбор существующего конфига nginx, редактирование конфига и `index.html`, генерация HTTP-шаблона, проверка `nginx -t` и откат файлов при ошибке применения.
- Установщик и обновлятор получают сборки из **martynov-dev/3x-ui**. Изменения исходного проекта подключаются отдельно через слияние `upstream/main`, после которого нужно проверять совместимость доработок.

## Установка и обновление

Сначала в форке должен быть опубликован релиз с бинарными файлами. Для сборки текущей ветки `main` используется тег `dev-latest`:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/martynov-dev/3x-ui/main/install.sh) dev-latest
```

Обновление установленной панели на сборку форка:

```bash
XUI_UPDATE_TAG=dev-latest bash <(curl -fsSL https://raw.githubusercontent.com/martynov-dev/3x-ui/main/update.sh)
```

Перед обновлением сохраните резервную копию. Стабильные теги доступны только при наличии соответствующего релиза в этом форке.

## Использование и ограничения

Расписание бэкапов включается в панели после выбора интервала и хранилища. Локальные архивы сохраняются в `/etc/x-ui/full-backups` или `$XUI_DB_FOLDER/full-backups`; отправка по SSH настраивается отдельно. Это копия приложения и выбранных файлов, а не образ всей системы. Полное восстановление пока выполняется вручную. Архив содержит пароли и ключи и не зашифрован на диске.

Для управления сайтом nginx должен быть установлен и запущен. Редактор работает с конфигами внутри `/etc/nginx` и сайтами внутри `/var/www` либо `/usr/share/nginx/html`. Выдача HTTPS-сертификатов и настройка Xray fallback выполняются отдельно.

Состав архива, настройка SSH, порядок восстановления, работа с nginx и команды получения обновлений оригинала приведены в [основном руководстве](README.md).
